# Prompt ↔ Schema ↔ Service ↔ DB — Enum / constrained-string audit

Generated by implementing the codebase verification plan.  
Scope: `be/app/prompts`, `be/app/model_providers/schemas.py`, `be/app/services`, `be/app/graph`, `be/app/db`, `be/app/db/models`.

---

## Executive summary

| Risk | Severity | Notes |
|------|-----------|-------|
| Prompt files **không được gọi LLM** (`prompt_behaviour_contract_builder`, `scenario_generation`) | Medium | Documentation drift; enums trong đó không ảnh hưởng runtime hiện tại. |
| `screen_type` prompt UI vs comment schema vs heuristic services | Medium | Prompt cho phép nhiều giá trị hơn comment trong `schemas.py`; backend heuristic dùng tập khác (`listing` absent in some branches). |
| `intent_kind` prompt vs `intent_eligible_targets` | High | Nhiều giá trị prompt **không** có trong map → không sinh candidate edges. |
| Composer `alternative_branch` vs `ComposedFlowA5.flow_type` comment (`validation_branch`) | Low | Chỉ drift comment/schema docs; runtime dict không validate vào `ComposedFlowA5`. |
| `Flow.flow_type` DB comment vs giá trị persist từ LLM | Medium | Comment legacy không khớp `single_step_outcome \| ordered_sequence \| branching_flow`. |
| Scenario audit prompt JSON có field không có trong Pydantic | Low | `average_reliability` trong `final_output_summary`; `traceability_missing` trong prose không có trên model. |
| Screen intent `primary_action.action_id` prompt cho phép null, schema require `str` | Medium | Có thể gây parse fail hoặc model provider ép kiểu tùy strict JSON schema. |

## 3. Runtime truth table (services + graph)

### LLM wiring (prompt ↔ schema)

| Prompt file | Service | `output_schema` |
|-------------|---------|-----------------|
| `prompt_ui_state_evidence_extraction_v2` | `ui_state_service` | `UIStateExtractionV2Result` |
| `prompt_screen_behaviour_intent_extraction_v2` | `screen_intent_service` | `ScreenIntentExtractionV2Result` |
| `prompt_intent_aware_flow_discovery` | `intent_aware_flow_discovery_service` | `UIFlowDiscoveryResult` |
| `prompt_scenario_evidence_audit` | `scenario_evidence_audit_service` | `ScenarioValidationResult` |

Các bước behaviour contract và scenario generation chạy trong `generate_tests_node` qua `generate_tests_service` (`run_behaviour_contract_builder`, `run_bdd_scenario_generation`); không còn các file LangGraph node riêng cho từng bước đó.

### `map_test_path` (`behaviour_contract_service.py`)

Maps `intent_type` → scenario slug:

`positive`→`happy_path`, `negative`→`negative_path`, `validation`→`validation_path`, `navigation`→`navigation_path`, `recovery`→`recovery_path`, `registration`→`registration_path`, `access_control`→`access_control_path`, `data_entry`→`data_entry_path`, default `unknown_path`.

Deterministic composer chỉ emits `intent_type` **`positive`**, **`negative`**, **`validation`** (from `main_success_path`, `negative_branch`, `alternative_branch`). Các intent_type khác trong schema/prompt behaviour contract **không** xuất hiện từ composer hiện tại.

### `candidate_edge_resolver_service.py` — `intent_kind` → eligible `outcome_state_type`

Canonical map lives in [`be/app/constants/edge_taxonomy.py`](be/app/constants/edge_taxonomy.py) (`INTENT_TO_TARGET_OUTCOME_COMPATIBILITY` / `eligible_targets`). **Layer 1** hard gates: [`candidate_edge_gates.py`](be/app/services/candidate_edge_gates.py) (cross-state capability, terminal source, target distinguishing evidence). **Layer 2** numeric score **0–100**: [`candidate_edge_scoring.py`](be/app/services/candidate_edge_scoring.py). **Layer 3** class thresholds + weak-band prune + confidence: [`candidate_edge_thresholds.py`](be/app/services/candidate_edge_thresholds.py). Resolver assigns `edge_kind` via [`candidate_edge_classification.py`](be/app/services/candidate_edge_classification.py). Duplicate transitions merge alternate paths into `alternative_action_sequences`. Output includes **`edge_score`**, **`edge_score_reasons`**, **`edge_risk_flags`**.

Kinds **có** map: `submission`, `confirmation`, `cancellation`, `selection`, `navigation`, `editing`, `deletion`, `search`, `feedback_acknowledgement`.

Kinds prompt **không** có trong map (→ `eligible_outcomes == {}` → không edges): **`data_entry`**, **`informative`**.

(Khi `intent_kind` falsy hoặc `informative`/`data_entry`, code `continue` sớm hoặc skip — đã có nhánh riêng cho `informative`/`data_entry`.)

### `flow_context_builder_service.py`

Overrides `outcome_state_type` to `empty_state` when `screen_type` in `dashboard`, `list`, `search_results`, `search` and text heuristics match. **`listing`** from UI prompt ≠ **`list`** checked here → có thể bỏ lỡ empty-state heuristic.

### `behaviour_contract_service.py` (`_compose_graph_flows`)

Uses `screen_type` lowercase in `["modal", "success", "confirmation", "error", "warning"]` for entry validation; không chứa `wizard`, `notification`, v.v.

### `intent_aware_flow_discovery_service.py`

Persists `flow_data.flow_type` directly to `Flow.flow_type` — giá trị là taxonomy LLM (`single_step_outcome`, …), không phải comment SQLAlchemy (`linear_flow`, …).

Stores `ordering_strength` / evidence từ LLM **as-is** (string); không normalize casing.

## 5. Confirmed mismatches & unused values

### Cross-layer conflicts

1. **`screen_type`**: Prompt ∪ heuristic ∪ composer sets không thống nhất; comment `schemas.py` lại khác prompt.
2. **`Flow.flow_type`**: Documentation trên ORM không phản ánh pipeline Agent 4.
3. **`scenario_type` vs DB comment**: Stored values là `*_path` không phải “positive/negative”.
4. **`validation_status`**: Prompt/schema audit có 4 status; model comment chỉ 3 giá trị.
5. **Evidence level casing**: Prompt prose uses capitalized labels; schema expects lowercase.

### Unused hoặc stale artifacts

- **`prompt_behaviour_contract_builder.txt`**, **`scenario_generation.txt`**: không được `PromptManager` gọi bởi code path hiện tại (registry vẫn có token limits cho tasks `behaviour_contract_builder` / `bdd_scenario_generation` — có thể phục vụ tương lai hoặc đường cũ).
- **`recovery_branch`** trong narrative behaviour contract / `ComposedFlowA5` comment: composer không emit → **`recovery` intent_type** không được deterministic path.

### Prompt-internal inconsistencies

- Behaviour contract §3.2 chỉ 3 mapping ngữ nghĩa nhưng JSON field `intent_type` mở rộng.

## 7. Recommended follow-ups (prioritized)

1. **Đơn nhất `screen_type`**: Cập nhật comment trong `schemas.py` khớp prompt **hoặc** thu hẹp prompt theo heuristic đang dùng; thêm alias (`listing`→`list`) trong `flow_context_builder_service` nếu cần.
2. **`intent_kind`**: Mở rộng `intent_eligible_targets` hoặc chỉnh prompt để không hứa hẹn kinds không được resolve edges.
3. **ORM comments**: Sửa `Flow.flow_type`, `BehaviourScenario.scenario_type`, `BehaviourScenario.validation_status` comments cho khớp persistence.
4. **Schema fixes**: Cho phép `Optional[str]` cho `ScreenIntentPrimaryActionA2.action_id` nếu provider strict; thêm `average_reliability` vào `FinalOutputSummaryA7` hoặc bỏ khỏi prompt ví dụ.
5. **`ComposedFlowA5.flow_type` comment**: Thêm `alternative_branch` hoặc đổi composer sang `validation_branch`.
6. **Normalisation**: `.lower()` khi persist `evidence_level` / `ordering_strength`.
